# 性能改善実験の記録

## 目的と現在の状態

この記録は、今回の実測に基づき Phasekeeper と isu-director を使って進めた private-isu の Go 実装の性能改善をまとめたもの。ベンチマークのスコア 60,000 を目標にしたが、**採用済みの変更で 60,000 の中央値にはまだ到達していない**。作業はユーザーの指示で一時停止した。

- 開始時 HEAD: `a7693aeec4cb9ed7148a0fb4f74e594d9b6e174a`。
- 停止時 HEAD: `637797fc557486f6c148638db8efd22bb496af63`。ローカルコミットのみで、push はしていない。
- 採用済み変更: コメント検索の複合索引と、`makePosts` の呼び出し内での準備済み SELECT 再利用。
- 実験用 DB には `001_comments_post_id_created_at` が適用されている。最後に試した `002_comments_user_id` は不採用後に down し、その migration ファイルを削除した。採用済み HEAD は再配置済み。
- もともとの `.gitignore`、`AGENTS.md`、`Taskfile.yml` の変更は保持している。アプリや migration に未コミットの実験差分は残していない。

停止直前の比較基準は中央値 **43,071**、最後に採用された準備済み文の比較では基準 **48,996**、候補 **50,417**。各計測は環境・時点が異なり、離れた計測同士を直接比較しない。後述の画像キャッシュは候補中央値 60,225 を記録したが、互換性の問題により採用していない。

## トークン使用量

このスレッドで確認できたゴール管理の使用量は次のとおり。ユーザーがゴールを解除・再設定したため、別々のゴールとして記録されている。

| ゴール | 確認時点 | 使用トークン |
|---|---|---:|
| 最初の isu-director 実験 | `blocked` | 60,730 |
| 「つづけて」 | `complete` | 39,347 |
| 最初の「6万になるまで」 | 解除前の表示 | 161,161 |
| 再設定後の「6万になるまで」 | `paused` | 497,775 |
| 確認できた合計 | 上記4件の単純合計 | **759,013** |

これはゴール管理で表示された `tokensUsed` の合計で、ゴール外の会話や後からの文書編集・push 作業、別プロセスの利用量を含む総請求量を示すものではない。計測方法の内訳は取得できていない。

## 手順と採否の考え方

各セッションで新規観測から始め、`task exp:measure` が取得した今回の生ログと、必要に応じて読み取り専用で取得した MySQL `performance_schema.events_statements_summary_by_digest` の前後差を使用した。Phasekeeper にローカルの `request.md` を渡し、analyze・implement・verify の結果と変更範囲を確認した。

[`experiments/policy.yml`](../experiments/policy.yml) の設定は `runs: 3`、`maxExperiments: 5`、`maxHours: 4`、`maxRetryPerWorkflow: 1`、`engineTimeout: 2h`。`minGainPercent` は未指定のため、各セッション最初の正常な HEAD 3回計測から `100 × (最大 − 最小) / 中央値` を算出して固定した。改善候補は HEAD を3回、続けて候補を3回測り、両方の trace 設定が一致し、候補が全回合格、中央値の増加率が正で閾値以上の場合に採用した。実装の互換性が満たせないと判断した候補は、スコアが高くても不採用とした。

SQL の時間はサーバ内の並列処理の**累積**であり、壁時計時間や HTTP 応答時間ではない。前後の取得窓には初期化や管理処理も含まれる。空のアプリログはアプリ内部の時間が不明であることを意味する。比較の `trace` は以下の計測ではいずれも `false`。

## 実験の経過

「不支持」は根拠や互換性を裏付けられず実装・候補計測を行わなかったもの、「打ち切り」はワークフローを完了できなかったもの。観測用の単回スコアは改善率の比較値ではない。

### 最初のセッション `s20261122`

| ID | 根拠・仮説 | 結果 |
|---|---|---|
| `obs-001` | nginx 生ログを自作ツールで集計。10,945 アクセス中、画像 GET は JPEG 4,623、PNG 1,228 | 観測採用。単回 11,315、合格。画像の所要時間は不明 |
| `exp-001` | 高頻度の画像取得を削減すれば改善する | 不支持。件数だけでは時間やスコアへの寄与を裏付けられない |
| `obs-002` | MySQL digest の前後差を観測 | コメント取得 LIMIT は 8,206 回・累積 426.625 秒、件数取得は 8,942 回・124.549 秒。単回 11,926、合格 |
| `exp-002` | `comments(post_id, created_at)` の索引でコメント検索の全走査を減らす | **採用**。基準 `[11933,12044,11955]`、中央値 11,955 → 候補 `[51992,49886,50550]`、中央値 50,550、**+322.84%**。両方全回合格。commit `68e382e` |
| `exp-003` | 投稿一覧を必要なデータだけ取得し全件取得を減らす | 不支持。同時刻順序・削除ユーザー等を含む等価性の根拠不足 |

`exp-002` 後の生ログ付き再計測は単回 49,113、合格。コメント検索の SQL は `created_at` が同じ行の順序を明示しておらず、索引による順序変化の可能性が残る。ベンチ合格だけでは全言語・全ケースの挙動を保証できない。

開始時には HEAD に `webapp/migrations` がないため runner の `git archive` が失敗した。ユーザーの許可を受け、isu-director の指示を変更し、[`scripts/exp.sh`](../scripts/exp.sh) が対象 ref に migration ディレクトリがある場合だけ archive に含めるよう修正。修正後の HEAD 3回は `[12105,11937,12155]`、中央値 12,105、全回合格。準備差分として保持している。
